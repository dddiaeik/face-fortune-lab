# Face Fortune Lab · 표정 운세 연구소

미소로 열어보는 오늘의 작은 행운. React + TypeScript + Vite로 만든 로컬 처리 방식의 엔터테인먼트 MVP입니다.

**재미를 위한 운세 체험이며 실제 미래를 예측하지 않습니다.** 얼굴 형태·표정으로 성격, 재산, 운명, 신원을 판단하지 않습니다. 표정은 카드 열기 입력에만 쓰입니다.

## 실행

Node.js 22.12 이상(검증: 24.22.1), npm 11을 권장합니다.

```sh
npm ci
npm run dev
```

브라우저에서 Vite가 출력하는 주소를 여세요. 카메라는 HTTPS 또는 localhost의 보안 컨텍스트가 필요합니다. 휴대폰에서 일반 HTTP LAN 주소로 접속하면 카메라가 동작하지 않을 수 있습니다. 카메라 없이도 버튼은 사용할 수 있습니다.

클라우드의 기본 npm 캐시 경로를 쓸 수 없는 경우:

```sh
npm ci --cache /workspace/.npm-cache
```

```sh
npm run typecheck
npm test
npm run lint
npm run build
npm run preview
```

별도 서버, 데이터베이스, 로그인, API 키, 환경변수는 필요하지 않습니다. 개발 서버는 `0.0.0.0`에 바인딩됩니다. 실제 배포는 이번 작업에 포함하지 않습니다.

## 사용법과 기능

1. 세 장의 카드 중 하나를 선택합니다. 기본값은 ‘새로운 씨앗’입니다.
2. **오늘의 운세 카드 열기**를 클릭·터치하거나 키보드로 실행합니다. 카메라 권한 요청과 모델 다운로드 없이 작동합니다.
3. 또는 카메라 사용 목적을 확인한 뒤 **카메라 시작하기**를 누르고 권한을 허용합니다.
4. 모델 준비 후 카메라 영상과 얼굴 랜드마크가 좌우 반전되어 표시됩니다.
5. 양쪽 미소 계수의 최솟값이 0.55 이상으로 700ms 유지되면 선택한 카드가 열립니다. 0.30 미만을 350ms 유지해야 재무장합니다. 얼굴 미감지 시 초기화합니다. 표본 간격이 250ms를 넘으면 진행 중인 미소 유지 판정은 재시작합니다.
6. 카메라 중지 또는 페이지 컴포넌트 종료 시 트랙, 애니메이션 루프, 모델을 정리합니다. 권한 요청·모델 로딩 도중 취소해도 늦게 도착한 리소스를 정리합니다.

`src/lib/smile.ts`의 `SMILE_CONFIG`에서 임계값과 유지시간을 조정할 수 있습니다. 초기 가설이며 조명·각도·기기별 실측 조정이 필요합니다. 얼굴이 여러 개라면 그중 최대 한 얼굴만 처리하며 특정 사용자를 식별하지 않습니다.

총운, 애정운, 금전운, 학업·취업운, 행운의 색상, 오늘의 한마디를 한국어 정적 문장에서 선택합니다. 실행 시점의 **Asia/Seoul 날짜 + 카드 ID + 항목명**을 FNV-1a 방식으로 해시합니다. 같은 버전·날짜·카드는 같은 결과입니다. 서로 다른 카드도 일부 문장이 우연히 같을 수 있습니다. 날짜는 카드를 여는 시점에 계산합니다.

## 성능 패널

‘개발자 패널’을 펼치면 다음을 볼 수 있습니다.

| 항목             | 집계 기준                                                                                      |
| ---------------- | ---------------------------------------------------------------------------------------------- |
| 분석 FPS         | 최근 최대 120개 표본의 `(개수-1) / 첫~마지막 분석 시작 시각 차(초)`; 렌더링 FPS와 다름         |
| 평균 / P50 / P95 | `detectForVideo()` 직전·직후 `performance.now()` 차이(ms); P50/P95는 정렬 후 nearest-rank 방식 |
| 표본 수          | 최근 최대 120회 추론, 얼굴 미감지 추론도 포함                                                  |
| 얼굴 감지        | 최근 분석 결과의 얼굴 존재 여부                                                                |
| 모델 로딩        | WASM resolver 시작부터 모델 초기화 완료까지 별도 측정(ms), 권한 대기·비디오 재생 제외          |

0개 표본 또는 1개 표본의 FPS는 0입니다. 표시 수치는 약 150ms마다 갱신하고 시작·중지 시 집계를 초기화합니다. 동일 `video.currentTime`은 다시 분석하지 않습니다. 분석은 최대 30회/초로 제한하지만 동기식 CPU 추론은 메인 스레드를 점유합니다. 저사양 모바일에서는 프레임 저하가 가능하며 Worker 전환은 후속 개선 항목입니다. 표본은 브라우저 메모리 안에서만 유지됩니다.

## 외부 리소스·라이선스·네트워크

카메라 권한 허용 후 다음 공식 배포 리소스를 불러옵니다. 별도의 자체 모델 재배포는 하지 않습니다.

| 리소스                                 | 실제 주소 / 라이선스                                                                                                                                                                                                                                        |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| MediaPipe Tasks Vision 0.10.32 JS/WASM | `https://cdn.jsdelivr.net/npm/@mediapipe/tasks-vision@0.10.32/wasm` 아래 `vision_wasm_internal.js`, `vision_wasm_internal.wasm` 등 실행 환경별 파일. MediaPipe Apache-2.0 ([공식 LICENSE](https://github.com/google-ai-edge/mediapipe/blob/master/LICENSE)) |
| Face Landmarker float16 v1 모델        | `https://storage.googleapis.com/mediapipe-models/face_landmarker/face_landmarker/float16/1/face_landmarker.task` · MediaPipe 공식 모델, Apache-2.0. [공식 모델 설명](https://ai.google.dev/edge/mediapipe/solutions/vision/face_landmarker#models)          |

런타임 허용 도메인: `cdn.jsdelivr.net`, `storage.googleapis.com`. 의존성 설치에는 `registry.npmjs.org`가 필요합니다. 브라우저에서 해당 리소스의 HTTPS/CORS 접근이 가능해야 합니다. 다운로드 요청에는 IP 등 일반 접속 정보가 포함될 수 있지만 카메라 프레임이나 랜드마크를 요청 본문에 넣지 않습니다. 재현성을 위해 라이브러리/WASM 버전과 모델 경로를 고정했습니다. npm 의존성은 lockfile로 고정합니다.

React/React DOM/Vite/Vitest는 MIT, TypeScript는 Apache-2.0입니다. 의존성의 각 배포 라이선스를 따릅니다. 외부 폰트, 분석 SDK, 광고, LLM, 유료 API는 사용하지 않습니다.

## 검증된 범위와 제한

- 타입 검사, Vitest 17개, ESLint, 프로덕션 빌드 통과.
- 실제 Chromium에서 수동 카드 선택·키보드 실행·390px 모바일 레이아웃·카메라 없음 오류를 확인했습니다. 수동 경로에서는 모델/CDN 요청이 발생하지 않았습니다.
- 카메라 스트림 및 추론은 모의 객체를 이용해 유지시간 선택, 동일 프레임 중복 방지, 취소·종료 정리를 검증했습니다.
- **실제 웹캠으로 얼굴 인식·랜드마크 정확도·미소 임계값·추론 성능은 미검증입니다.** GPU도 검증하지 않았으며 구현은 CPU delegate입니다.
- 현재 클라우드에서 WASM 주소는 HTTP 200이지만 모델 도메인은 네트워크 정책에 의해 CONNECT 403입니다. 설정 초안 저장 도구도 오류를 반환하여 허용 목록 변경의 저장을 확인하지 못했습니다. 카메라 검증 전 환경 설정에서 `storage.googleapis.com` 접근 허용이 필요합니다. 버튼 체험과 로컬 빌드는 이 제한과 독립적입니다.
- 실제 터치 기기와 Safari는 미검증입니다.
