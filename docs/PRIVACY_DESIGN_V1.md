# Privacy Design V1

## 처리 목적과 최소화

카메라는 사용자가 ‘카메라 시작하기’를 누른 뒤에만 요청합니다. 처음부터 목적과 로컬 처리 안내를 보여주며, 사용하지 않아도 모든 카드 콘텐츠에 접근할 수 있습니다. 오디오 권한은 요청하지 않습니다.

영상 → MediaPipe 랜드마크·표정 계수 → 미소 입력 이벤트까지 모두 브라우저 안에서 처리합니다. 서버 업로드, 얼굴 사진/영상 저장, 신원 식별, 성격·운명·재산 추론은 구현하지 않습니다. Canvas는 화면 표시용이며 `toDataURL`, 캡처, MediaRecorder 기능을 사용하지 않습니다.

## 저장과 종료

- 랜드마크·계수는 현재 분석 프레임의 일시 객체로만 사용합니다.
- 최근 120개 성능 표본은 시간과 소요시간만 포함하며 얼굴 좌표가 없습니다.
- 선택 카드와 운세 결과는 React 메모리에만 있고 새로고침하면 사라집니다.
- localStorage, IndexedDB, 쿠키, 서버 데이터베이스에 앱 데이터를 기록하지 않습니다.
- 중지·종료·실패·초기화 취소 시 트랙과 모델을 해제합니다. 진행 중인 외부 모델 다운로드 자체는 라이브러리 내부에서 취소되지 않을 수 있으나, 완료 후 반환된 모델은 즉시 해제합니다.
- JS 런타임의 메모리 수거 시점이나 OS/브라우저 자체 보관 정책까지 앱이 통제한다고 주장하지 않습니다.

## 외부 요청

초기 앱 파일은 호스트에서 받습니다. 카메라 사용 시 공식 모델 및 WASM을 Google Storage / jsDelivr에서 다운로드합니다. 원격 서버는 IP, 접속 시간 등 일반 네트워크 메타데이터를 볼 수 있습니다. 모델/WASM 파일이 HTTP 캐시에 남을 수 있으나 사용자 얼굴 데이터는 넣지 않습니다. 외부 폰트·분석·광고 SDK는 없습니다.

코드에서 얼굴 데이터를 포함하는 fetch/upload 경로는 없습니다. Chromium 수동 체험 테스트에서 모델/CDN 요청이 없는 것을 확인했습니다. 실제 카메라 세션의 전체 네트워크 감사는 모델 도메인 차단과 웹캠 부재로 미검증입니다. 카메라 검증 시 Network 패널에서 다운로드만 있고 영상·랜드마크 업로드가 없는지 확인해야 합니다.

## 사용자 고지

화면에 ‘재미를 위한 운세 체험이며 실제 미래를 예측하지 않습니다’를 표시합니다. 표정은 카드 입력에만 사용하며, 운세 문장은 서울 날짜와 카드 ID로 정합니다. 유용한 개인정보 보호 방식은 기술 한계를 숨기지 않고 사용자가 카메라를 켜지 않을 선택권을 보장하는 것입니다.
